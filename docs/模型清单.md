## 二、只有 4 个真实模型（其余都是配置残留）

| 用途 | 生效模型 | 变量 |
|---|---|---|
| 文本 | `doubao-seed-2-1-pro-260628` | `TEXT_MODEL` |
| 视觉（判定 + 反推） | `qwen3-vl-plus` | `VLM_MODEL` |
| 出图 | `wan2.7-image` | `IMAGE_NATIVE_MODEL` |
| 出片 | `wan2.2-i2v-flash` | `VIDEO_MODEL` |

**`IMAGE_PROVIDER=dashscope`**，中转站那套（`gpt-image-2.5-sunburst`，¥0.02/张）**已于 2026-11-02 从 `.env` 整体删除**——它当前不参与任何调用，留着只是噪音。要切回中转站需重新填三项并同步 `PRICE_IMAGE=0.02`（`providers/relay_image.py` 的代码没删，一直可用）。

**`.env` 现在是 30 行，只有 4 组模型 + 预算单价 + 外部依赖。** 删掉的东西与原因：

| 删除项 | 原因 |
|---|---|
| `DEEPSEEK_API_KEY/BASE_URL/MODEL` | S1 最早的文本方案，`config.script_llm` 全项目**无任何调用点** |
| `DOUBAO_API_KEY/MODEL`、`ARK_IMAGE_MODEL`、`ARK_VIDEO_MODEL`、`ARK_VIDEO_RESOLUTION` | 开图开片前的「待定」字段，已被 `IMAGE_NATIVE_*` / `VIDEO_*` 取代 |
| `DOUBAO_BASE_URL` | 唯一非空的一项，值与 `config.py` 的默认值完全相同 |
| `IMAGE_API_KEY/BASE_URL/MODEL` | 中转站，见上（代码保留、密钥已移出） |
| `TEXT_DISABLE_THINKING`、`VIDEO_SUPPORTED_SECONDS`、`JUDGE_PASS_LINE`、`JUDGE_FLOOR_LINE`、`VLM_THINKING`、`VLM_CONCURRENCY`、`MAX_RETRY_PER_SHOT` | 值本来就等于代码默认值（1 / 5 / 75 / 60 / 1 / 4 / 2），留着重复一遍；真要改时再加回对应行 |

唯一要记住的：**这 7 个「默认值项」以后如果要调，`.env` 里得自己补一行**，否则改了文档不改配置不会生效。`.env.example` 已同步成同一结构。

## 四、三个开关会改行为

| 开关 | 当前值 | 作用 |
|---|---|---|
| `VLM_THINKING=1` | 开 | 判定开深度思考。实测关掉后会把「四分之三侧视导致一只眼露出面积变小」判成眉眼不一致，**制造假阴性**。代价是单次 150–170 秒 |
| `VLM_CONCURRENCY=4` | 4 | 判定并发。开思考时串行 30 对要 80 分钟以上 |
| `TEXT_DISABLE_THINKING=1` | 关思考 | 写剧本 193 秒 → 28 秒、token 9891 → 1299，产出无差别 |

阈值也绑在模型上，换判定模型必须重新标定：

```
JUDGE_PASS_LINE=75    ≥75 通过（qwen3-vl-plus 实测同人最低 85、异人最高 65，取空档正中）
JUDGE_FLOOR_LINE=60   <60 放弃重试（重试一次 ¥0.02，误弃一条坏首帧要赔 ¥1.00）
VIDEO_SUPPORTED_SECONDS=5   wan2.2-i2v-flash 只支持 5 秒，档位表就是模型能力边界
```

## 五、一个仍存在的账目缺口（另一条已修）

**① 剧本那一步在账面上是 ¥0。**

`PRICE_LLM_PER_CALL` 没配，`config.py` 默认 `0`。所以 `chat-text` 调了 15 次、账本一分钱没记。真实量级约 3–5k token / 次、¥0.005 一部，不影响预算判断，但**“实扣 ¥12.27” 严格说少算了剧本那一毛几分**。`.env` 里已留了一行注释掉的 `PRICE_LLM_PER_CALL=0.005`，要精确记账去掉注释即可。

**② 旧注释已修（2026-11-02）。**

原来 `.env` 里 `VLM_MODEL` 上方那段注释还写着「改用同系列、配额独立的 `doubao-seed-2-1-turbo-260628`」，而实际值早就是 `qwen3-vl-plus`——那是 10-27 从 pro 切到 turbo 时留的，后来判定 429 改用百炼的 qwen 解决，注释没跟着删。重写 `.env` 时已按现状改写，现在的注释与值一致。

## 六、换模型要动哪里

| 想换的 | 改哪几行 | 必须连带改 |
|---|---|---|
| 判定 / 反推模型 | `VLM_API_KEY` / `VLM_BASE_URL` / `VLM_MODEL` | `JUDGE_PASS_LINE`、`JUDGE_FLOOR_LINE` 重新标定；`PRICE_VLM_PER_CALL` 按新报价填 |
| 剧本模型 | `TEXT_API_KEY` / `TEXT_BASE_URL` / `TEXT_MODEL` | 无（`PRICE_LLM` 先补上） |
| 出图 | `IMAGE_NATIVE_*`（或切 `IMAGE_PROVIDER=relay` 走 `IMAGE_*`） | `PRICE_IMAGE` **必须同步**：两家差 10 倍，单价错了预算闸等于没有 |
| 出片 | `VIDEO_API_KEY` / `VIDEO_BASE_URL` / `VIDEO_MODEL` | `VIDEO_SUPPORTED_SECONDS`、`PRICE_VIDEO_PER_SEC`、`VIDEO_RESOLUTION` |

**铁律：两个不同厂商的配置不能互相回退。** 10-29 踩过一次——判定的 `VLM_*` 从方舟换到百炼，而 S1 的 key/base 回退到 `VLM_*`，于是它拿着豆包的模型名去请求百炼端点，直接 404 `model_not_found`，流水线第一步就停。模型名和端点是绑定的，回退只搬了 key/base 不搬 model，必然错配。这也是为什么要单列 `TEXT_*` 四个变量。
