# 交付清单（2026-11-02 结项）

这个项目做的是：**把一段短剧创意跑成一条人物长相前后一致的成片**——剧本结构化 → 定妆照
→ 首帧 → 一致性判定与定向重取 → 图生视频 → 合成（字幕/配音）→ 交付报告。

结项后最终保留的东西就是下面这些。除此之外的过程文件已经清掉，清理明细在第五节。

## 三、怎么跑

```bash
# 起 Web 服务（界面在 http://127.0.0.1:8000）
python run.py --mode api

# 命令行跑一部（真实调用，必须显式授权付费）
python run.py --project-id <id> --confirm --allow-paid

# 零成本演练（全 mock，不调任何外部 API）
python run.py --mock --project-id <id> --auto

# 只重跑某一镜（改了分镜描述后必须用它，否则 S3 见 done 会跳过）
python run.py --project-id <id> --rerun-shot shot_03 --rerun-reason "白布应该在奶龙手上" --allow-paid
```

界面上的三个停点：**停 0** 选角色来源 → **停 1** 改角色卡与分镜 → **停 2** 看正脸。
三步都要人点确认才会往下走，因为这个顺序刻意把"花钱的大头（六镜视频）"放在所有人工确认之后。

## 六、已知限制（结项时仍未解决的）

1. **C2 浏览器通道已整体移除**。不是代码问题，是即梦的会员墙：点「生成」只弹套餐窗，
   没有"继续普通生成"，积分从头到尾没变（152 → 152），说明提交从未真正发生。
   那批浏览器接管代码已在结项时删除；要恢复先解决账号权益，再重新实现。
2. **LLM 仍可能不遵守事实清单**。2026-11-02 已把「反推」前移到 S1 之前（见下），
   实测模型会照着参考图写（奶龙的性别年龄写"无"、动作写"抬起戴着白色手套的手"），
   但这仍然是**提示词约束**，不是结构强制。所以 S3 开跑前那道"动作提到的人不在场上"
   的预检不能撤。
3. **重出单镜不能"无中生有"**。理由会拼进提示词，但模型只能画 `character_ids` 里的角色。
   要让某角色进这一镜，必须先把该角色加进这一镜的出场角色，否则"把女生换成豆包"的结果
   是"女生没了、豆包也没来"。
4. **单镜重出后成片会过期**。系统会删掉旧 `final.mp4` 并把阶段退回 running，
   需要再点一次「继续生成」重新合成（合成免费，只重跑拼接，不重出视频）。
5. **预算闸在**。单镜重跑约 ¥1.20，六镜整跑约 ¥8–12。超预算会在调用前就抛错并停住，
   不会烧到一半才发现。

### 2026-11-02 补做：S1 读图再写剧本

原来 S1 只拿创意文本编人物，写出来的角色卡是「23-27 岁人类男性」这种凭空设定，分镜动作
也按人类的习惯写（"凑近男生的手臂"）；反推只在**之后**覆盖外貌，改不了已经写进分镜的
称谓与动作。现在的顺序是：

```
上传参考图 → VLM 先读成「人物事实」→ S1 拿着事实写名字/性格/分镜
          → 出剧本后再用反推覆盖一遍外貌（命中缓存，不重复花钱）
```

拿同一张奶龙图、同一段创意实测（项目 `s1ref`，只跑了 S1，花 ¥0.02）：

| | 旧流程 | 新流程 |
|---|---|---|
| 奶龙的性别/年龄 | `男` / `23-28岁`（硬填） | `无` / `无` |
| 奶龙的外貌 | "23-27 岁人类男性，肤色白皙" | "椭圆形黄色头部…体表为均匀亮黄色…约 3 头身，四肢短小，手部为白色手套状结构" |
| 分镜动作 | "女孩…凑近男生的手臂" | "豆包…伸手要把白色布巾缠到奶龙的手臂上" |
| 与出场角色的一致性 | `shot_02` 只列豆包，动作却写"男生的手臂" → 画出真人手臂 | 每镜两人同框时 `character_ids` 都齐，预检 0 冲突 |
